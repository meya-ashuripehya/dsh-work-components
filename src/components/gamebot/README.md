# GameBot（dsh-work-components 内嵌）

本目录是 **GameBot 本体 + MCP 桥**，随 `dsh-work-components` 一起维护并随包发布，不依赖外部仓库。

## 布局

玩家向 NPC 私聊使用 `/minaret agent tell <席位编码> <内容>`，例如 `/minaret agent tell seat-5 你好，请只私聊回复我`。沿用 `/minaret` 的命令权限；只投递给目标席，不广播、不给另一席、不写绑定房间。1.2.2 起发送者本地回显 `<目标 NPC 名称> 私聊内容`。当前运行旧模组时需先退出游戏并更新。

隔离验收脚本 `node scripts/mc-autonomy-live.mjs <输出目录> [运行秒数]` 默认 600 秒，允许 1–1800 秒；到期停止控制循环并回收测试 body 与模型进程。正式宿主联调同样应设置有界测试及结束停用检查。

- `index.mjs` — 两张游戏卡（`gamebot-minecraft` / `gamebot-civilization`，设置页隐藏）与共享 Python 环境的准备
- `process.mjs` — 共享 REST body 的启停（引用计数；只杀本插件拉起的进程；退出钩子在插件生命周期里注册）。启动时把 `data/member-token` 的路径放进 `GAMEBOT_MEMBER_TOKEN_FILE`。令牌不打印。复用外部 body 时成员接口返回 503，需要从工作台重启。
- `members.mjs` / `members-tools.mjs` — 成员连接、观察、动作与接管接口。房间轮聊只开放 `mc_observe`、`mc_status`；其他控制工具保留给显式手动接管。调用者来自席位，不来自参数。
- `fields.mjs` — 每张卡的设置字段（`lib/client.js` 里的字段由 `scripts/gen-gamebot-fields.mjs` 生成）
- `pyproject.toml` + `src/gamebot/` — Python 代码（FastAPI REST + `mcp_bridge`）。只用 `pyproject.toml` 的依赖列表，代码经 `PYTHONPATH` 运行，不安装、不往本目录写文件

可写状态都在插件数据目录 `<DSH_HOME>/data/dsh-work-components/gamebot/`：`.venv/`（共享 Python 环境）和 `data/`（`game-configs.json`、记忆等，含服务商密钥明文）。

## 使用

1. Minecraft 与文明 VI 不在设置页显示。启用键仍是 `gamebot-minecraftEnabled` / `gamebot-civilizationEnabled`。没有「下载安装」：第一次启用时自动用托管的 uv 建 Python 3.12 venv，并**从 PyPI 下载安装依赖**（约半分钟到几分钟，走设置里的下载代理）。装好后写 `.dsh-gamebot-ready.json`；中途失败下次会重建。
2. 启用后自动启动 REST（默认 `http://127.0.0.1:8766`）并挂载该游戏的 MCP 桥
3. 关闭全部游戏卡 → 停止我们拉起的 body；插件停用 / 卸载时同样会停掉

**每次应用/会话启动，所有游戏卡默认关闭**（需重新打开启用）；`gamebotUrl` / `gamebotRoot` 会记住。

Minecraft 可用席位来自绑定聊天室的已启用成员（旧配置仍按 Minecraft AI 表交集回退）。选择席位只登记资格，不生成 NPC。在游戏中执行 `/minaret agent spawn <席位编码> [名称]` 后开始自主陪玩；`remove` 后自动连接不会重建它。同世界重进恢复已加入成员。需要新版 Minaret 提供持久化世界 UUID，旧模组会提示更新并暂停自主动作。

每席独立运行观察、决策、执行、验证循环：动作后至少 2 秒再决策，安静时默认 10 秒，可 `wait` 5–30 秒；玩家消息和定向 AI 消息可提前唤醒。首轮工具为模组实际声明的 `say`、`move_to`、`look_at` 与本地 `wait`，普通模型文字只用于目标记录，不会发到公屏。模型调用 90 秒上限，错误按 5/15/30 秒退避，相同目标三次失败冷却 60 秒。

绑定房间的滚动摘要与最近 24 条有效消息进入游戏决策；本席最近 20 条公开决策结果按世界与席位持久保存。游戏公开发言回写房间一次，其他 AI 发言可进入感知。私聊只供当前席实时处理，不写房间、共享记忆或轨迹正文。房间轮聊不驱动游戏动作。成员会话 id 为 `minecraft-<编码>`，不启动 GameBot 大脑。`mc_status` 及成员 status REST 提供自主运行诊断；接管/恢复使用 `mc_takeover` / `mc_resume`。成员 REST 须 `X-Gamebot-Member-Token`，原有路径保持，新增受鉴权的 `/v1/minecraft/members/{id}/autonomy` 接收宿主诊断状态。

**Minaret 模组（服务端 NPC）**：源码在 `minecraft-neoforge-bridge/`；设置页「打包下载」或 `gradlew jar` 产出 jar。协议 v2：每成员一条 WebSocket（`AgentBridgeServer`），hello 带 `agent_id`；legacy 单控制端仍走 `BridgeServer`（仅无歧义时）。旧存档单个 NPC 保持 `legacy_unbound`，须 `/minaret agent adopt <编码>` 后再绑定成员。

## 双脑警告

不要同时让 DSH 桌面大脑与 GameBot 自带大脑对同一游戏发动作。

## 可选覆盖

- `gamebotUrl`：REST 地址
- `gamebotRoot`：指向外部 GameBot 目录（留空则用本目录）。填写时，它自己的 `data/` 与 `.venv` 留在那个目录里，首次加载会从它的 `data/game-configs.json` 一次性导入设置
- `GAMEBOT_MINECRAFT_BRIDGE_DIR`（环境变量）：Mineflayer 驱动用的外部 `minecraft-bridge` 目录。桥不随包提供，未设置时 Minecraft 只用 minaret 驱动

## 移动目标与确认（Minaret 1.2.3）

服务端观察增加 `standable_goals`，提供附近经过支撑、身体碰撞与危险检查的脚部坐标；半砖等使用实际碰撞形状顶面，不统一套用方块高度加一。`path_checked: false` 表示尚未验证整条路径，实际移动仍可能失败。模型优先使用这些位置；无候选时重新观察或等待，不能声称已抵达。

宿主使用同一到达半径等待和验证新快照，不在两格阈值处提前停止。一旦世界或维度改变、手动接管或动作回执失败，不将位移计为完成。轨迹增加确认原因与剩余距离，供区分无新快照、目标未到达和动作失败；结果不明时只观察，不自动重发。

## 持续任务与可见感知（Minaret 1.3.0）

自主工具增加 `navigate_to`、`follow_entity`、`explore_area`、`stop_task`、`inspect_blocks`，只暴露握手声明支持的工具。旧模组缺少持续任务能力时提示更新，不回退到高频小步调用。旧 `move_to` 仍可通过显式手动接管使用。

任务提交经原成员 `/actions` 返回 `accepted` 和 `task_id`，代表开始执行而非到达。服务端按游戏刻持续推进最长16格的路段，普通路段不唤醒模型；导航默认180秒有效游戏时间，跟随默认保持3格、超过5格继续，探索默认16格半径、120秒并返回。未加载区块明确失败，不强制加载。一个席位只有一个任务，新任务先停止旧任务；重复目标不会重启导航，已到达目标不会产生新的完成事件。断线、停用、移除、接管和换世界均取消旧任务。

任务正常执行期间普通模型决策间隔60秒，无任务默认15秒；点名、私聊及任务终态可提前唤醒，公开闲聊只合并为上下文。发言不会取消导航。超过3秒没有推进的新快照时挂起决策并使旧回合失效；恢复需两份序号及游戏时间推进的新观察。UI标注观察停滞与任务暂停，导航超时按游戏刻计算，不包含暂停时间。

模型默认观察改为 `terrain_summary`、最多24个 `points_of_interest`、当前任务和最多24个可见落脚点；不发送原始地下方块。兴趣点在原始512条截断之前筛选，并要求暴露表面及眼部射线可见，矿物相邻分组合并；危险/功能/矿物/未知类型预留4/6/6/4条，其余补齐，每ID最多3条。按需查询最多32条，同样不能透视。历史兴趣点按世界、维度、席位隔离，并标注 `last_seen`。成员 `mc_observe` 也使用可见语义视图；底层REST观察保留原始调试数据。

模组 common 配置 `perceptionRules` 可用分号追加规则：`id|类别|优先级` 或 `#标签|类别|优先级`，例如 `mod:machine|functional|10;#c:ores/tin|ore|5`。类别为 `danger`、`functional`、`ore`、`unknown`、`terrain`、`ignore`；标签与交互接口优先识别用途，未知模组命名空间不等于机器。

隔离验收脚本默认只用 Gemini（seat-5），Windows上启动前必须等独立看门狗就绪。测试运行目录包含临时鉴权文件，不应整体复制交付；只交付经挑选的轨迹、状态、结果与视频。
# Minecraft 1.4.0：挖掘、物品栏与自动拾取

成员 NPC 沿用各自 36 格持久化背包。玩家可右键 NPC 打开物品栏并存取物品；正在操作物品时暂不打开，已打开的菜单在手部事务开始时失效，避免同一工具被重复改写。背包、工具耐久、可见掉落物及最近实际拾取结果进入游戏决策上下文。

新版握手声明 `minecraft.world.harvest_with_tools` 后，自主模式才开放 `break_block`。目标必须可见、可达并匹配 `expected_block`；开始挖掘前须停止活动导航任务。模组从全部 36 格选择符合采收要求且速度较快的工具，必要时与当前快捷栏槽交换。缺少可采收工具时返回 `missing_tool`，不破坏目标。泥土、木头等允许徒手获取的方块不强制要求工具。挖掘复用 NeoForge 生存玩家的进度、掉落、附魔、耐久与方块破坏事件；原版或模组仍可能不产生对应方块物品。宿主为单次目标签发短期凭证，保留原有协议鉴权。

已连接的 NPC 每 5 个游戏刻检查身体附近的掉落物，不隔墙、不远程吸取；原版拾取延迟、归属、组件堆叠及模组拾取事件仍生效。背包满时物品保留在地上，部分拾取只转移能容纳的数量。自动拾取不会抢占导航；更远的可见掉落物由 AI 决定是否靠近。方块破坏确认与物品入包确认独立，只有背包变化及实际拾取记录支持“拿到了”。本版不新增合成、熔炼或自动生产。

# Minecraft 1.5.0：自主放置与丢出

新版握手声明 `minecraft.world.place_from_inventory`、`minecraft.inventory.drop_safe` 后，才向自主决策开放 `place_block`、`drop_item`。放置使用全部36格背包中的真实材料，复用已有放置流程、目标状态读回和单格签名；自主模式先停止导航、靠近目标，不另开自动移动流程。目标已满足时不消耗材料；占用、不可见、够不到、缺材料时拒绝。

丢出按物品ID及一个堆叠中的数量执行，先确认实体成功生成再扣库存。回执和新观察中的数量减少必须同时成立。NPC对自己刚丢出的同一掉落实体暂停自动拾取60个有效游戏秒，其他玩家仍可拾取；不会把“已丢出”当作“对方已收到”。跨重进和掉落物合并场景未专项验收。

同一交流任务上下文中，相同的已确认丢出请求默认作为重试跳过。模型只有明确要追加另一批时才使用 `additional_drop=true`；新玩家请求也允许再次丢出。跳过动作不会扣物品，并明确反馈“此前已完成，未重复执行”。完成记录是本次控制连接的有界内存状态，不承诺跨重连任务幂等。

# Minecraft 1.5.1：可见方块状态

兴趣点及 `inspect_blocks` 的每条方块记录增加 `state`，包含当前可见方块的全部注册属性：布尔值保留布尔类型，整数保留数字，朝向等枚举使用注册名称。原始扫描接口的既有状态格式保持不变；不读取或公开方块实体NBT、容器内容。

同ID、不同状态的资源不合并，同一ID的代表位置优先覆盖不同状态，仍遵守24条兴趣点及每ID最多3个位置的预算。带有点燃、开关、电力、作物年龄等交互状态的方块进入功能兴趣点候选，避免蜡烛等在普通地形采样中被截掉。熄灭营火按功能方块展示；燃烧营火仍为危险。

可见性检测针对实际轮廓形状的表面进行射线检查，支持蜡烛等小于完整方块的形状；封闭或被遮挡的方块仍不暴露。状态变化由新观察更新；同位置历史记录会被新观察替换，未重访记录仍标记last_seen，不作为当前状态。年龄、能量或电力等属性需要按对应方块规则解释，缺失属性表示未知。
