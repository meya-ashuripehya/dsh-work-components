# 移动与放置功能补全计划

状态：评审定稿；本轮仅更新计划，尚未执行代码修改或游戏实测。候选导航采用固定离散目标集合，后续实现由 Cursor 任务书交接，等待 Shiro「执行」。

## 目标与范围

让 AI 发出一个明确的移动或放置请求后，底层完成对应动作，返回可核验的结果和具体失败依据。按 Shiro 的要求实行结构化、最小职责、复用实现。

本期只补全 NeoForge 服务端 NPC 的移动与放置，以及必要的协议、Python 透传、测试和文档。蓝图调度器只约定接口，不在本期实现；不扩展采集、合成、容器、多智能体工地协调或其他游戏驱动。

工作目录：`S:/TRIX/dsh-workbench/src/components/gamebot/`。旧目录 `S:/TRIX/TRIX-GAMEBOT/MOVED.md` 已声明以此内嵌副本为日常代码，旧目录仅作历史对照，不双写。

运行基线：Minecraft 1.21.1、NeoForge 21.1.228、Java 21。保留已有动作账本、agent_id、request_id、generation、取消和连接生命周期机制，避免另造通信或任务系统。

## 已核对的现状

- `ServerActionDispatcher` 集中实现移动与放置。移动使用原版 Navigation，由 tick 推进；当前到达阈值固定为 1.6，距离上限 96，并在导航结束后有限次重发。
- 当前 `place_block` 直接执行单次放置；距离或视线不满足时不会调用移动。
- 放置从快捷栏 0–8 查找材料；主背包有材料会返回 `unsupported`，材料完全缺失返回 `item_not_found`。
- `FacingPlacement` 只枚举水平四向；以完整 defaultBlockState 加请求属性比较预测结果，未指定属性也被意外约束。
- 放置构造支撑面点击参数时没有传递 `hit_offset`，已有点击坐标能力未贯通到真实放置链路。
- 原接口 `face` 当前表示“支撑块位于目标块的哪一侧”，实际被点击面是其反方向。不能把它悄悄改成另一种含义。
- 放置后存在 `effect=unverified` 的返回。它不能被上层当作已确认完成，也不能直接触发重复放置。
- `player=null` 不足以证明实体碰撞被跳过。NPC 自身碰撞、门/床第二格和原版放置调用链仍须用目标版本源码与真实世界测试查明，不能把此前推测写成事实。

## 职责与调用关系

`蓝图调度器 → 放置服务 → 移动服务 → 原版 Navigation`

`放置服务 → 原版 BlockItem 放置接口 → 世界状态读回`

移动只接受通用导航目标、到位要求和移动约束，负责路径、绕障、进度、到达与停止；它不认识待放方块、朝向或图纸。

放置接受落点、方块和状态约束，负责构造交互上下文、选定交互站位、必要时调用移动、执行一次放置并核验。它不实现 A*、障碍绕行或自己的路线追踪，也不修改落点或放宽指定状态。

蓝图调度器只负责图纸依赖与顺序，调用放置并消费结果；不接收“请你替我找站位”的工作。

保留一个内部单次放置原语。默认对外 `place_block` 完成必要移动后放置；若已有调用方需要原地模式，增加明确的 `auto_move=false` 选项，而不是复制两个放置实现。参数默认行为变化须同步更新能力说明。

## 一、移动服务

### 输入与路径

保留 `move_to(x,y,z)`，增加经过校验的到达容差；内部支持通用、有限、离散的候选目标点集合，供交互服务调用，不接收模糊目标区域。移动模块从固定集合中计算可达路线，不携带任何方块放置知识。

放置服务先按当时可读的世界状态筛出满足交互距离、实际点击点视线、身体空间、可停留支撑及禁入约束的有限离散站位，再一次性提交固定且有数量上限的候选集合。可停留和通行判定复用移动公开能力。移动在行走前进行一次有界多目标规划，按可达性及路线成本选定一个候选点，不要求按直线距离逐点步行尝试；不能动态补充候选。集合中没有可达点就直接返回。

选定点后，整个移动阶段锁定该候选；途中障碍只允许在共同预算内绕向同一个目标，不切换集合中的另一个点。到位必须返回原始候选标识、选定目标坐标和最终实际脚部坐标，不能将实际位置冒充候选圆心。几何初筛只说明检查时的候选合格，不保证动态世界和到位偏差不会令复检失败；施工容差必须明确且足够严格，不继承固定 1.6 的宽松阈值、不暗中放宽。

放置到位复检失败或原版放置失败后立即终止，不再提交旧集合或新集合、不回到选点、不调用第二次放置。调度器只消费结果，挂起或交回；不能自动换候选、换请求号重派同一施工步骤。只有明确的新外部意图才能开始新动作，且必须遵守已有未知副作用的只读核验规则。移动内部同目标绕障与放置失败后换位重放严格区分，蓝图调度器始终不选择站位、不实现导航。

复用原版 Navigation 和碰撞/通行能力；楼梯、台阶、跳上一格等服从 NPC 实际导航能力。不能通行就报告失败，不自动挖墙、搭桥、垫脚、拆门或改地形。

支持移动约束的统一入口：禁入区、世界边界、危险地形与区块加载限制。禁入约束必须作用于路径搜索及实际路径跟随，不能只检查终点或发现已经踩入后才判失败。动态变化时在进入违规段之前停止或由移动模块有界重规划。

禁入约束由请求上下文显式提供并由放置透传，移动只消费通用区域约束，不维护田地归属或工地占位数据库。本期没有工地协调模块：未提供约束时按空集合处理，并在结果中明确未应用外部禁入区，不能声称已保护 Shiro 的田。输入为有版本的不可变快照；如调用链已有可更新约束源则复用，更新在主线程进入下一路径段前生效；本期未接入在线更新时必须如实声明其限制，不能假装知道后续占位变化。普通地形、实体与障碍变化仍由移动的现场检测处理。

本期以已加载区域为范围，沿用现有距离限制并明确错误含义，不通过强制加载区块、传送或无限扩大搜索掩盖失败。

### 到位、进度与生命周期

完成条件采用实际脚部坐标与请求的容差，并确认碰撞体可停留、导航已停止；不能仅凭 Navigation.isDone() 或进入原固定 1.6 半径就宣告施工到位。

施工调用使用更严格的到位要求，容差作为显式配置，结合 NPC 体积和真实可停留位置验证；不能为取得成功回执而偷偷放大阈值。

移动拥有卡住检测与有限重规划，区分无可达路径、路径未完成、卡住、超时、目标卸载、被取消。预算包括总时限与重规划次数，不能每次重规划重新计时。

取消、断连、实体消失、世界切换或过期 generation 均终止导航。移动阶段取消须在服务端确认停止导航、清除本动作的后续驱动后，才可释放动作占用并报告取消完成；请求已失效不能继续放置。不要求清除重力、外力等非本动作造成的运动；断连时无法送达的回执记入账本供查询。复用已有动作账本和每实体动作占用机制，避免外部 move 与 place 的内部导航同时争抢一个 NPC。

输出至少包括目标、最终实际位置、剩余距离、规划/重规划次数、耗时及终止原因；途中关键证据可查询，避免每 tick 向 AI 刷屏。

## 二、放置服务

### 请求语义

沿用 `pos/block_id/state/face/max_distance` 现有字段和坐标结构，贯通 `hit_offset`。新增字段在 Java 校验、协议文档、Python 构包和工具能力声明中保持一致。

`state` 是必须满足的指定属性集合，不代表强制所有未指定属性保持默认值。例如只指定 `facing=east`，不能暗中同时要求楼梯一定为 bottom、门一定为 left hinge。

保留现有 `face` 的支撑侧语义，在文档和结果中分别使用 `support_pos`、`clicked_face`，消除方向歧义。指定 `face` 或 `hit_offset` 时严格遵守，不自动换面或改点击位置来凑成功。

未指定点击约束时，可在有界候选中选择合法支撑面、点击位置和六向观察上下文。复用方块自身的 getStateForPlacement / BlockItem 规则判断可产生的状态，不写一套通用方块规则，也不用 setBlock 强改最终朝向。

补全六方向上下文，覆盖上下活塞/发射器等竖向放置；补全六方向的视线排序和适用的 yaw/pitch，不能只把水平枚举改成六个值而仍返回水平观察。

`open=true` 等需要后续交互才能得到的属性，如果本次原版放置不能产生，则如实返回状态不可达；本期不自动串联开门、点火或红石操作。

### 执行过程

1. 校验参数、身份/动作占用、世界与区块。读回目标：方块和请求属性已匹配则返回 `already_present`，不移动、不扣料。
2. 只检查现有材料。本期维持快捷栏取料边界，不实现背包自动搬运、不依赖尚不存在的备料模块；区分材料不存在与材料仅在非可用槽位，附可确认的槽位和数量事实后返回。外部如何备料不在本期范围，调度器不因此接手槽位搬运细节。
3. 构造原版交互上下文。无支撑、状态不可达等已能直接查明的失败立即返回；诊断只复用原版接口与世界事实，不重写原版放置判定器。
4. 当前位置具备交互距离、视线和安全身体位置时直接执行；否则按真实 NPC 体积、眼高、支撑面点击点生成有限站位集合，调用移动服务一次。站位选择不使用固定眼高、固定甜点环或整格空气的简化假设。候选点须能容纳实际碰撞体，具备可停留的支撑且避开危险位置；复用移动服务公开的通行/可停留判定，不在放置层再实现一套地形规则。不得把任意空气格当作站位，也不硬编码脚下必须是整块实心方块而排除合法台阶等地形。本期不新增游泳或飞行施工模式。
5. 到位停止后按真实位置重新检查交互距离、射线、目标及材料，重新构造上下文，避免走路途中世界变化导致旧预测失效。任一复检不通过即附具体检查结果返回并停止，不再次调用移动、不回到候选选择。身体不能与待放方块形状重叠；该约束作为站位安全检查，不冒充原版碰撞结论。
6. 复用原版 BlockItem 放置接口执行一次。被拒绝即返回，不再次移动重放，不换方块、落点或状态，不自行搭临时设施。
7. 读回世界与材料变化。单格比对 block_id 和请求属性；门、床等多格方块额外核验相关格和一致性。多格附带效果按原版语义处理，不只查看首格就报全部完成。

任何 mutating 调用之前再次校验取消和动作有效性；移动阶段与放置阶段共用同一个外部 request_id、deadline 和取消链，内部调用不作为第二条竞争动作入队。

世界已经变化但读回不匹配时，明确返回未确认/部分效果及现场证据，停止本请求；不自动拆除、回滚、补另一格或重试。放置一旦进入原版调用，取消或超时不能等同于“未执行”。在服务端主线程记录提交边界和副作用事实，若仍能完成只读核验则如实记录；不能可靠核验时返回 effect=unverified，并在账本保留待核验状态，不当作可安全重试的失败。完成核验不允许追加任何补救性写世界动作。

账本区分未提交、已提交待核验、已核验及部分效果；同一 request_id 的重复投递只能返回/查询已有动作与证据，不重复调用原版放置，同 ID 不同参数须拒绝。网络超时或取消不得删除提交记录、释放后触发重放；结合现有 generation 与连接生命周期明确记录保留及重连范围。若断线、记录过期或重启后无法证明是否执行，标为结果未知并要求读回，不能宣称端到端 exactly-once。

### 失败诊断

先追查 Minecraft 1.21.1 / NeoForge 21.1.228 的实际调用链、NPC 碰撞属性和已有适配器，厘清 canPlace、canSurvive、实体碰撞、可替换条件和多格放置的关系。

错误按事实细分：参数不合法、区块未加载、目标占用、材料缺失/槽位不可用、缺少支撑、指定状态不可达、无交互站位、移动失败、距离不满足、视线阻挡、放置被拒绝、读回不匹配、超时或取消。最终名称优先复用既有错误码；新增码全链路声明。

能证明具体实体或具体规则导致失败，才报告对应原因，并带阻挡位置/实体标识/规则检查结果。原版只给出笼统拒绝且无法可靠定位时，保留 `action_rejected`，标记 `diagnosis=unknown`，附已检查事实与未确定项；不猜成“实体挡住”，不把查不明伪装成查明。

## 三、结果契约

沿用现有 `ok/effect/error_code/evidence` 结构，避免另起平行响应协议。增加稳定的阶段字段与必要证据；所有上层适配器必须透传。

建议 evidence 包括：`stage`、原始目标/请求状态、实际站位与眼位、支撑块/点击面/点击点、实际距离与限制、导航结果、放置接口结果、落地实际状态、相关格变化、材料前后数量、原因证据及诊断确定性。

只有读回满足目标及请求状态才算确认完成。已经存在可算已满足；`unverified`、部分效果和超时未知不得当作已确认完成，Python 结果归一化和工具展示都要保留这一区别。

调度器及其他调用者收到 unverified、超时未知或部分效果时，只能以原 request_id 查询账本，或通过独立只读接口核验现场；不得自动生成新 request_id 重派同一放置。核验无法消除歧义时挂起交回，不能仅因账本不存在或超时就认定没有副作用。本期只落实并测试调用契约，不实现蓝图调度器。

给 AI 的摘要使用简短明确的中文，例如“移动失败：目标区域无可达路线，未执行放置”或“放置被拒绝：原因未确定；目标仍为空气，材料未减少”。完整结构化 evidence 可供检查，不能只有一句条件不满足。

6. 补测试、运行 Java/Python 检查，更新 bridge README 与协议说明，交付构建产物路径和实际验证记录。

优先修改 bridge 的 `action/`、必要的 `protocol/`、导航扩展与 `AgentEntity` 接入点，以及对应 Python 适配层和测试。类名按现有结构选取，不为了套层而增加接口。

## 五、验收

| 场景 | 通过条件 |
| --- | --- |
| 空地到点、隔墙有绕路、楼梯/台阶 | 路线合法，按请求容差停稳；不穿墙、不假报到达 |
| 终点封闭、路径结束未到、动态障碍、超时 | 有界结束，原因及最终坐标可查，无无限重发 |
| 路径经过禁入区但终点合法 | 规划绕开；无绕路则失败，全程不进入禁区 |
| 移动/放置途中取消、断连、旧 generation、并发动作 | 停止导航，失效请求不能继续放置，结果不串实体 |
| 固定集合含可达/不可达点、行走途中所选路线受阻 | 初次规划可选可达点；选定后仅绕向同一点，绝不改选或追加候选；返回候选标识及真实位置 |
| 近处放置、远处放置、隔墙绕行后放置 | 近处不多走；远处只复用移动；实际到位且视线满足才放 |
| 无可达交互位置、无支撑、缺料、非快捷栏有料 | 返回对应事实；不改落点、不动无关方块、不盲重试 |
| 未指定 state；只指定 facing；楼梯上下半；原木 axis | 只约束指定属性，点击坐标生效，落地状态可核验 |
| 活塞/发射器上、下朝向 | 六向上下文真实工作，无法产生的状态明确拒绝 |
| 床/门完整空间、第二格阻塞、NPC/其他实体占位 | 真实世界行为查明，多格结果准确；拒绝原因无臆测 |
| 走到一半目标被占、材料变化 | 动作前重读；返回当前事实，不覆盖现场 |
| already_present、重复 request_id、读回不匹配 | 不重复扣料；未确认结果不得当作成功继续施工 |
| 到位后视线/距离/材料复检失败 | 返回现场事实，不重新导航、不调用原版放置 |
